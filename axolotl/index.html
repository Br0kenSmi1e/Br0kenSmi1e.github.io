Logic Is Type Checking

November 2026

I recently built axolotl, a proof checker in about 600 lines of Rust. This post is the one idea it taught me: checking a proof is type checking a program — not by analogy, but because they are the same activity. Here is the shortest path I know to seeing it.

A proposition is defined by its evidence

What is "A and B"? Whatever you can give as evidence for it: evidence of A, together with evidence of B — a pair. What is "A implies B"? A method that turns any evidence of A into evidence of B — a function. What is "false"? Something with no possible evidence at all.

Each proposition is completely pinned down by saying what counts as evidence for it. That is what a proposition is.

A type is defined by its members

What is the type of natural numbers? Whatever counts as a member: zero, successor of zero, and so on. What is a function type? Whatever you can call with an A to get back a B.

A type is completely pinned down by saying what counts as a member of it. That is what a type is.

Put the two paragraphs side by side: a specification of evidence, and a specification of members — the same kind of thing. So read the first list again as types: "and" is a pair type, "implies" is a function type, "false" is an empty type. A proof of a proposition is an element of the type. A true proposition is a type that has an element; a false one is a type that happens to be empty.

So checking a proof is checking a type

"Is this a proof of the proposition?" now means "is this an element of the type?" — and that question is mechanical. Every shape of evidence has exactly one way to check it. To check a function as evidence of "A implies B": assume evidence of A, check that the body produces evidence of B. To check a function call: does the argument's type match the domain? Each check is local; the evidence announces its own shape; no search, no insight, no judgment. That is why a small, dumb machine can do it — and why the machine can be trusted: it never guesses, it only verifies.

An example, in full. Proposition: "if A, then A". Evidence: the identity function — give it evidence of A, it hands the same evidence back. Checking it means checking one function body. Done. The proof is three characters long, and a computer can confirm it.

That is the whole idea

Everything else is this idea scaled up. "For every number n" is a function whose return type depends on the input — one more constructor, nothing new conceptually. Equality, numbers, induction: same pattern, more constructors. Axolotl implements the smallest version that works, and its kernel — the part that must be trusted — is about 250 lines.

The idea has a name, Curry–Howard, and a slogan: propositions are types, proofs are programs. But the slogan is easy to memorize and hard to feel. The version that made it click for me is the one above: evidence and membership are the same notion, so logic and type checking were never two things.
